# OpenCode turn lifecycle

The runner submits each browser turn once through `session.promptAsync`. Its ten-second deadline bounds only the local ACK request. It does not impose an inference deadline or authorize a retry. Native message IDs use the pinned OpenCode 1.18.31 ascending `msg_` format; the browser UUID remains the journal/request identity. Existing saved credentials, session ID, fixed model, workspace context, images, questions and bypass permissions are retained.

A turn stays Working and retains its Sprite Tasks hold while native work is active or uncertain. The runner reads native messages, then status, with five-second control deadlines and one-second pauses. It matches the exact native user ID and assistant parent ID. Only a final assistant (excluding tool-call/unknown finishes) or correlated error followed by a fresh authoritative idle read settles a normal turn. A successful status map omits idle sessions; a failed/malformed read does not establish idle. Stream events received during a status read invalidate that read. Clean stream EOF reattaches to the same runtime.

Stop does not cancel an in-flight submission. After the exact current message becomes durable, the runner aborts the native session and obtains a fresh idle read before releasing the hold. This also handles acceptance after a lost/timed-out ACK. Abort/control timeouts retain the hold rather than claiming the native work stopped. A definite rejected HTTP request still requires successful messages/status evidence that it was not accepted. Ambiguous server errors or transport loss never cause automatic inference retries.

Repeated connection refusal on both authenticated loopback control endpoints ends the turn with a local-runtime connection error. Timeouts alone do not establish runtime death. A reachable runtime with an indefinitely ambiguous submission remains protected until acceptance/completion, Stop confirmation, or runtime loss can be established; elapsed time alone cannot prove that a delayed POST will never execute. This is intentionally distinct from native provider authentication, rate-limit or inference errors.

Validation is entirely local. `tests/agent-opencode-runner.test.ts` runs the actual runner, pinned SDK HTTP/SSE, journal and Tasks API against a loopback native-runtime double. `tests/agent-opencode-long-turn.test.ts` runs the actual pinned native binary against one loopback fake-provider stream lasting 305 seconds; it requires Node 24.18.0 and is opt-in via `CIVIC_SPARK_LONG_TURN=1`. The fixture isolates its home/config/data/cache and disables provider discovery/default plugins/updates. No participant code or paid provider executes.

Local validation: the pinned native proof passed in 309.02 seconds with one inference request, at least six Tasks PUTs, no release while still Working beyond 300 seconds, and one release at success. The earlier native pass took 308.43 seconds. Full check passed 358 tests across 60 files, with the long-turn and capacity-stream opt-ins skipped in the default suite; the long-turn opt-in was run separately. Biome, application/runtime typechecks, production build and a clean 153-file deployment context passed. Full mobile and specialized agent browser checks passed, with screenshots inspected at phone/desktop/short widths and both themes.

The persistent-connection browser fixture exposed an unrelated sign-out assertion issue: deliberately invalidating the session can reject in-flight files/changes reads with 401. The fixture now reports and permits only those exact read types in the explicit sign-out phase, retaining all other console assertions. The corrected connection suite and the final fullcheck both passed. Original diagnostic logs remain in the worktree artifacts for review.

Browser checks use isolated mocked runtime transports. Physical iOS/Android keyboard/picker behavior, live paid inference and deployed runtime acceptance remain unverified. Root owns integration, publication, deployment and live acceptance.
