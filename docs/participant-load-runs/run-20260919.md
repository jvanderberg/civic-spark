## Findings

1. **429 is our own provisioning cap.** `CIVIC_SPARK_MAX_PROVISIONING`/`maxProvisioning` = 2; p03's third concurrent Sprite create was refused in 10 ms with "Workspace preparation is busy" (request df9451d3, no Sprite call). The client retried; p03 reached its workspace ~35 s after the others.
2. **502 reproduced once, classified.** Resuming p03 at 01:37 for inspection: `POST /api/workspaces/:id/agent/prepare` → 502 "The Sprite tools could not be installed or verified" (request 0c8f40ed). Backend: the `sprite exec` upload/setup command exited 1 after 30,042 ms with stderr classified `timeout` (CLI-side; our limit was 120 s). A retry ~80 s later succeeded in 7.6 s. This is a transient Sprite exec timeout right after wake. The web client treats this as a blocking error with a Retry button. Whether the September 18 run's five 502s were this path cannot be proven; that run had no request IDs.
3. **409 not reproduced.** Code paths returning 409: wake with stale generation ("Workspace changed. Refresh before connecting."), prepare across a generation change ("Workspace changed. Reconnect to continue."), agent prepare without a ready Sprite. No evidence links the earlier 409 to any of these.
4. **p03's failure was in the scripted observer, not the platform.** The Sprite journal shows the completion question at 01:14:52.957, `Working`, reasoning text, `WE'RE ALL GOOD`, `Turn complete`, `done outcome=success`. The server's `lastUsedAt` is 01:15:04.374 (the done touch). The browser client executed its post-done refresh at 01:15:04.539 (off-cadence files/changes/file burst, identical to p01's at 01:12:04.305). No agent reconnect occurred (no further credentials/prepare calls). The runner never registered that done. Most likely cause: the observer keeps a 10,000-event ring buffer using `shift()`, and the completion loop pre-computes `start` as an array index; text events are emitted per streamed delta and p03's turn streamed 41,356 characters (one 37,697-character message), so once the buffer was full every new event moved the window past the done. Not directly verified because observed events are not persisted.
5. **Idle pause behaved as designed** after that: no activity for five minutes after 01:15:04 → held idle at 01:20:05 → four 423s, "Sprite paused" dialog. The runner then waited out the rest of its 20-minute turn timeout (until 01:34:58) because it only watches for a done event.
