## Failures

**Sixteen idle holds during long turns.** p01, p02, p13, p15, p16, p25, p29, p33, p34, p35, p38, p39, p41, p45 and p48 stopped between 20 and 26 minutes with one of three faces of the same event: "This session no longer has workspace access", "Sprite paused dialog is shown", or "workspace held (idle)". Backend `lifecycle.idle` records show 38 workspaces released as idle between 00:05 and 00:20 with `idleMs` just over 300 s. The idle limit is five minutes of no participant input; the runner's completion cadence is also five minutes. With short turns the agent usually answered "all good" at the first check; with the real-data prompt many agents answered "not yet", the workspace then sat quiet for exactly five minutes, and the hold landed as the runner sent the next question. A real person reading an agent's answer for five minutes would have hit the same pause. p06 timed out waiting for a completion-check response after 33 minutes on the same mechanism.

**Two file-list races at the hello step.** p09 and p46 failed at 03-hello-file in the arrival minute exactly as p41 had the day before: the file was written (blob PUT 200) but the explorer list came from a request that started before the write, and the refresh that carried it reapplied the previously open file over the new one because its guard read a ref that React had not yet re-rendered. Screenshots show `.gitignore` open and no `hello.txt` in the explorer.

## Changes made

1. **Attended idle limit.** While someone has the workspace open in a visible tab (the per-workspace events socket is attached; it closes when the tab is hidden), the idle limit is `CIVIC_SPARK_WORKSPACE_ATTENDED_IDLE_MINUTES`, default 30, instead of the five-minute limit. A tab left open still releases. Tests cover both limits.
2. **File-list race.** Opening a file bumps a sequence number; a refresh that began before an open never reapplies its snapshot. A caller that just wrote a file waits for any in-flight refresh and forces another pass so the list reflects the write. The toolbar smoke reproduces a late file list and asserts the new file stays open and listed.

With both fixes the same run would have been about 49 of 50.
